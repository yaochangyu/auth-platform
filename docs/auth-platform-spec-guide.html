02 OAuth 2.1 授權碼模式 (PKCE) 與 Vue 同意流程

平台全面遵守現代 OAuth 2.1 安全草案規範：全面廢除隱含模式（Implicit Flow）、禁止密碼認證流程、強制啟用 PKCE（S256 演算法）。

1
第三方發起授權請求 GET /connect/authorize
帶入 client_id、redirect_uri、response_type=code、scope=openid profile email、以及關鍵的 code_challenge（S256 雜湊）。若缺少 PKCE 或使用 plain 演算法，伺服器立即中斷回絕。
2
單點登入 Session 檢查與未登入重定向 Cookie Authentication & Security Stamp
Auth Server 解密主網域 Session Cookie 並即時至資料庫檢查安全性戳記（防密碼已變更的無效登入）。
• 已登入：接續步驟 3。
• 未登入：302 導向 member.1111.com.tw:8080/login?returnUrl=...。登入成功後跳回原請求。若帶有 prompt=none 則直接回傳 login_required。
3
第一方自動同意 vs 第三方同意票證簽署 Consent Boundary
• 受信任第一方應用程式（如 developer-web、admin-web）：直接免同意核發短效單次使用的授權碼（Authorization Code）。
• 第三方應用程式且無授權紀錄：後端以 Data Protection 將授權上下文加密封裝為 5 分鐘短效、綁定會員且單次使用的 consent_id，302 跳轉至 member-web 的 /oauth/consent?consent_id=...。
4
Vue 同意畫面與權限縮減防竄改 POST /api/v1/oauth/consent
前端 Vue 呼叫介面取得應用程式名稱與請求權限範疇（Scopes）。會員確認勾選（權限範疇只能縮減不可擴充，openid 必選）。
• 點擊同意：建立 OpenIddict 授權記錄，核發授權碼，302 跳回客戶端 redirect_uri?code=...&state=...。
• 點擊拒絕：依 RFC 6749 以 302 跳轉回 redirect_uri?error=access_denied&state=...。

03 權杖換發與 Refresh Token Rotation (RTR) 攻防機制

在 /connect/token 端點，客戶端使用授權碼換取權杖，並在過期前使用 Refresh Token 續期。本平台實施了最高標準的權杖輪替與重複使用偵測機制：

存取權杖 Access Token (RS256 JWT)

  • 生命週期：短效 15 分鐘。
  • 簽章演算法：RS256（非對稱私鑰簽名）。私鑰持久化於 auth-signing-key.pem，公鑰公開於 /.well-known/jwks.json。
  • 離線驗證：各內部資源伺服器（developer-api、admin-api）無須連線 Auth Server 資料庫即可高吞吐本機驗簽。

更新權杖 Refresh Token Rotation (單次輪替)

  • 生命週期：30 天滑動過期。
  • 單次使用：每次換票時，舊的 Refresh Token 立即在資料庫中標記作廢，並核發一組全新的 Refresh Token。
  • 寬限期歸零：絕不允許延遲過期，避免並行利用漏洞。

權杖重複使用偵測與授權家族全面撤銷 (Family Revocation)

攻防場景：若攻擊者竊取了會員已使用過的舊 Refresh Token 並嘗試換票，OpenIddict 核心即刻判定發生「權杖洩漏攻擊」，系統將立即自動撤銷該會員授予該客戶端的整筆授權（Authorization）。所有先前核發的新舊 Refresh Token 與關聯的 Access Token 立即全數失效，將資安損害降至最低。

04 伺服器對伺服器 M2M 與無固定 IP 雲端安全簽章

在微服務後端通訊中，現代雲端常具備動態出口 IP，靜態 IP 白名單無法滿足安全需求。本平台設計了雙軌 M2M 鑑權模型：

軌道 A：OAuth 2.1 Client Credentials

機密型客戶端（Confidential Client）以 client_id + client_secret 向 /connect/token 換取無會員介入之 15 分鐘 M2M Access Token（sub: client_id），不簽發 Refresh Token，降低長期金鑰暴露風險。

軌道 B：API 金鑰 + HMAC-SHA256 簽章

提供微秒級直連驗證，不需先至 Auth Server 換票：

  • 環境前綴：ak_live_...（正式）/ ak_test_...（測試），明文僅展示一次，資料庫僅存 SHA-256 雜湊。
  • API 密鑰加密：以 Data Protection 對稱加密保護，供驗簽還原。
  • HMAC 規範：客戶端送出 X-Signature 與 X-Timestamp。
// HMAC-SHA256 簽章計算字串規範（由 auth-shared 通用中介軟體強制校驗） String toSign = Method + "\n" + PathAndQuery + "\n" + Timestamp + "\n" + Hex(SHA256(Body)); // 防禦點 1：Timestamp 公差限定 ±5 分鐘，徹底防禦封包側錄重放攻擊（Replay Attack） // 防禦點 2：Body 雜湊綁定，中間人一旦竄改參數或 Payload，簽章立即不符 // 防禦點 3：中介軟體採用 CryptographicOperations.FixedTimeEquals 常數時間比對，防禦時序攻擊（Timing Attack）

05 管理員後台、一鍵緊急斷路器與不可篡改稽核日誌

針對突發性客戶端洩漏或惡意攻擊，系統管理員具備全平台最高等級的緊急處置權利。

一鍵緊急斷路器 (Circuit Breaker)

當管理員將某個應用程式切換為 Suspended（停用）時，系統在單一資料庫交易內執行以下連鎖作廢動作：

  1. 資料庫列級排他鎖定（Row Lock），防止並行衝突。
  2. 即刻作廢該 App 擁有的所有 API 金鑰。
  3. 即刻撤銷 OpenIddict 上的所有 有效授權紀錄（Authorizations） 與 Tokens。
  4. MultiSecretApplicationManager 即刻阻擋後續任何授權碼發放、Token 換發與 M2M 驗證。

資料庫觸發器防禦之不可篡改稽核日誌

所有管理員操作（審核、狀態切換、金鑰重設）皆寫入 audit_logs 表：

  • 記錄操作人 actorMemberId、時間、可信轉送客戶端 IP、動作與前後變更詳情。
  • PostgreSQL 觸發器鐵律：資料庫層級掛載觸發器，嚴格禁止任何 UPDATE、DELETE 或 TRUNCATE 指令，即便系統有 SQL 注入漏洞也絕無法銷毀證據。
